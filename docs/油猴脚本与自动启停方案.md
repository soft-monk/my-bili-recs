# 油猴脚本（M3）+ 服务自动启停 方案

## 0. 直接回答两个问题

**Q1：改成油猴脚本还能用吗？**
能用，但**油猴脚本不能替代本地服务**——浏览器里跑不了 TF-IDF 双轴模型。
正确架构是：**油猴脚本 = B站页面里的前端触点；`serve.py` = 本地引擎**。两者配合，不是二选一。

**Q2：能不能"开浏览器自动开服务、关浏览器自动关服务"？**
能。推荐 **W1 守护脚本（watch.ps1）**：它常驻内存，每 5 秒检查浏览器进程——
有浏览器就拉起 `serve.py`（作为自己的子进程），浏览器全退出就把它杀掉。
再加 `serve.py --idle-exit` 兜底，防止守护脚本异常时服务残留。

## 1. 架构

```
B站页面（Tampermonkey 油猴脚本）
  ├─ 视频页：兴趣/价值 双轴打分  ──POST /api/score────┐
  ├─ 首页/推荐流：卡片贴分+重排   ──POST /api/predict──┤
  ├─ 心跳（每 30 秒）            ──GET  /api/ping─────┤
  └─ 顶栏「我的精选」按钮 ──────> http://127.0.0.1:8765/
                                        ┌─────────────┴──────────────┐
                                        │  serve.py（本地引擎）        │
                                        │  data/scores.csv · 双轴原型  │
                                        └────────────────────────────┘
```

## 2. `serve.py` 需要新增的接口

| 接口 | 方法 | 请求体 / 参数 | 返回 | 用途 |
| --- | --- | --- | --- | --- |
| `/api/ping` | GET | — | `{"ok":true,"train_count":N}` | 心跳（必须极轻，不跑模型） |
| `/api/score` | POST | `{bvid,title,tags,interest,value}` | `{"ok":true}` | 页面打分写回 scores.csv |
| `/api/predict` | POST | `{"items":[{bvid,title,tags},...]}` | `{"picks":[{bvid,pred_interest,pred_value}]}` | 推荐流卡片贴分/重排 |
| `/api/picks` | GET | `?top=20` | `{"picks":[...]}` | 给油猴面板/其他界面用 |
| `/` | GET | — | HTML | 现有每日精选页（保留） |

**两个必须处理的细节：**
1. **CORS**：B站页面（https://www.bilibili.com）请求 `http://127.0.0.1:8765` 是跨域。
   用 `GM_xmlhttpRequest` 可绕过；但为兼容普通 `fetch`，仍要加响应头
   `Access-Control-Allow-Origin: *`，并实现 `OPTIONS` 预检（返回 204 + 允许的 header/方法）。
2. **混合内容（mixed content）**：https 页面请求 `http://127.0.0.1` **不会被拦**——
   Chrome/Firefox 把 `127.0.0.1` 和 `localhost` 视为"可信来源"（potentially trustworthy origin），
   这是浏览器规范明确的例外。所以不需要给本地服务上 HTTPS。

**空闲自退（兜底）：**
```python
# serve.py --idle-exit 600
# 后台线程每 30 秒检查：now - last_request_ts > idle_exit → server.shutdown()
```

`recommend.py` 需同步抽一个 `predict_items(items, ...)` 函数（给任意视频列表打分），
`compute_picks()` 内部复用同一套原型计算，避免逻辑重复。

## 3. 油猴脚本设计（`userscript/bili-recs.user.js`）

### 3.1 元数据块

```javascript
// ==UserScript==
// @name         bili-recs 双轴打分
// @namespace    https://github.com/soft-monk/my-bili-recs
// @version      0.1.0
// @description  B站视频双轴打分 + 推荐流贴分 + 每日精选入口
// @match        *://*.bilibili.com/*
// @grant        GM_xmlhttpRequest
// @grant        GM_setValue
// @grant        GM_getValue
// @connect      127.0.0.1
// ==/UserScript==
```

> `@connect 127.0.0.1` 必须声明，否则 `GM_xmlhttpRequest` 会被 Tampermonkey 拦截。

### 3.2 功能清单

1. **视频页双轴打分条**：在标题下方注入两组 1~5 星（兴趣 / 价值）。
   解析 bvid（URL 或 `window.__INITIAL_STATE__.bvid`）、标题（`h1.video-title`）、
   标签（`.tag-panel .tag` 文本；抓不到就用分区名兜底）→ `POST /api/score`。
2. **心跳 + 状态徽标**：右下角小圆点（绿=服务在线，灰=离线），每 30 秒 `GET /api/ping`。
3. **离线缓冲**：服务不在时，打分先存 `GM_setValue` 队列；心跳恢复后自动补传。
   （这样即使忘了开服务，分数也不会丢。）
4. **顶栏「我的精选」入口**：打开 `http://127.0.0.1:8765/`。
5. **（可选，第二阶段）推荐流重排**：`MutationObserver` 监听 `.bili-video-card` →
   批量 `POST /api/predict` → 卡片角标显示预测分；低于阈值的灰化或隐藏；
   面板里有开关和阈值滑块。

### 3.3 关键代码片段

```javascript
const API = 'http://127.0.0.1:8765';

function api(method, path, data) {
  return new Promise((resolve, reject) => {
    GM_xmlhttpRequest({
      method, url: API + path,
      headers: { 'Content-Type': 'application/json' },
      data: data ? JSON.stringify(data) : undefined,
      timeout: 4000,
      onload: r => { try { resolve(JSON.parse(r.responseText)); } catch (e) { reject(e); } },
      onerror: reject, ontimeout: reject,
    });
  });
}

// 打分（失败则进离线队列）
async function submitScore(item) {
  try {
    await api('POST', '/api/score', item);
    toast('已记录：兴趣' + item.interest + ' / 价值' + item.value);
  } catch (e) {
    const q = GM_getValue('pending', []);
    q.push(item); GM_setValue('pending', q);
    toast('服务未启动，已暂存本地，稍后自动补传');
  }
}
```

## 4. 自动启停：三个方案对比

| 方案 | 机制 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **W1 守护脚本（推荐）** | `watch.ps1` 常驻，每 5 秒看浏览器进程：有则拉起 serve.py（子进程），全退出则杀掉 | 完全符合"开浏览器即用、关浏览器即停"；无需浏览器弹窗 | 多一个常驻 PowerShell 进程（约 30MB） |
| **W2 空闲自退（零常驻）** | `serve.py --idle-exit 600`，10 分钟无请求自动退出；油猴心跳负责保活 | 无守护进程，最简单 | 关浏览器后最多等 10 分钟才退出；**且退出后无法自己重新启动**，仍需 W1/W3 负责"开" |
| **W3 自定义协议（按需启动）** | 注册 `bilirecs://` 协议 → 启动脚本；油猴检测到离线时显示"启动服务"按钮，点击触发 | 完全按需，无常驻进程 | 需要点击一次 + 浏览器首次弹"是否打开外部应用"确认框 |
| **W4 油猴拉起 + 心跳自退（推荐）** | 油猴 ping 失败 → 触发 `bilirecs://` 拉起服务；服务靠"心跳缺失"自行退出 | 无常驻进程、无开机自启、无定时轮询，完全"用完即走" | 每个浏览器会话首次需点一次启动按钮（可勾"始终允许"） |

**推荐组合：W4**（最贴近"油猴拉起、关闭即停"的设想）——见 4.1 的完整链路。
如果之后觉得"每次点一下"麻烦，再叠加 W1 守护脚本即可，两者不冲突。

### 4.1 W4：油猴拉起 + 心跳自退（无守护进程）

**先明确一个硬边界**：网页 / 油猴脚本**无法直接启动本机进程**（浏览器安全模型，不存在这样的 API）。
所以"油猴自行拉起后台"必须由操作系统转一手——注册自定义协议 `bilirecs://`，由 Windows 执行启动脚本。

启动链路（B站页面是入口，服务由它按需拉起）：

```
B站页面油猴脚本 → 点「我的精选」
   ├─ GET /api/ping 在线 → 直接打开 http://127.0.0.1:8765/
   └─ 离线 → 触发 bilirecs://start（首次需点确认，可勾"始终允许"）
             → Windows 执行 start-server.ps1 → 隐藏启动 serve.py
             → 油猴轮询到在线 → 打开 http://127.0.0.1:8765/
```

保活 / 退出链路（**心跳来自推荐界面本身，不来自 B站标签页**）：

```
推荐界面 http://127.0.0.1:8765/ 每 60 秒 GET /api/ping   ← 生命线（浏览器定时器自动发，你无需任何操作）
   ├─ 界面开着（任意一个标签）→ 服务保持运行
   └─ 界面关闭 / 浏览器关闭 → 心跳消失
      → serve.py 连续 180 秒（3 个心跳周期）没收到任何请求 → 自行 shutdown() 退出
```

- **为什么不依赖 `beforeunload`**：浏览器不保证发出该事件，崩溃或强杀更不会。用"心跳缺失"判定才可靠
- **看视频多久都不影响**：心跳是页面里的后台定时器，不是你的操作。看 40 分钟长视频、或把精选页切到后台，
  定时器照跑；Chrome 对后台标签的定时器会把间隔节流到约 60 秒，所以参数取
  **"60 秒心跳 + 180 秒宽限"**，容忍三次连续节流或丢包
- **标签被浏览器丢弃（省内存模式）时**：心跳彻底停止 → 服务在 180 秒后退出；回到精选页会显示「唤醒服务」按钮，
  一键走同一套 `bilirecs://` 链路拉起；期间在 B站页面打的分存在离线队列，不会丢
- **备用方案（更省流量的升级项）**：把心跳换成 SSE 长连接——页面与服务之间保持一条连接，
  连接断开即代表界面关闭（检测更即时，还能顺便推送"新推荐已生成"）。代价是需要重连逻辑，
  默认先用 60 秒轮询，够用且简单
- **多标签天然支持**：任意一个精选页标签活着，服务就活着
- **心跳放在推荐界面而不是 B站标签页，有两个好处**：
  1. 语义正确——服务的生命周期绑定它自己的界面，B站标签页只是打分入口
  2. 修掉一个真实 bug——若只按"最后请求时间"算空闲，精选页开着十分钟不操作，服务会空闲退出，
     页面上的「满意/踩雷」按钮就全失效了；有了界面心跳，界面活着服务必然活着
- B站标签页的油猴脚本**不持续心跳**，只在点「我的精选」时 ping 一次判断在线状态；
  它的打分走离线缓冲队列——服务没启动时先存 `GM_setValue`，进入推荐界面后自动补传
- **优点**：无常驻守护进程、无开机自启、无定时检查，完全按需
- **代价**：每个浏览器会话首次需要点一次启动按钮。Chrome/Firefox 不允许"无用户手势"的外部协议跳转，
  这是浏览器层面的限制，绕不过去；勾选"始终允许"后，后续会话的体验接近零摩擦
- **边界**：服务存活完全跟随推荐界面。只开 B站页面、不开推荐界面时，服务不会运行
  （打分进离线队列，不丢数据）
- **想要真正零点击**：只能升级为 Chrome 扩展 + Native Messaging（扩展有权限直接调用本机程序），
  但那就不再是油猴脚本了——需要额外装扩展 + 注册 native host 清单，收益有限

配套文件：

| 文件 | 作用 |
| --- | --- |
| `register-protocol.ps1` | 一次性写入 `HKCU\Software\Classes\bilirecs\...` 协议注册（当前用户即可，无需管理员） |
| `start-server.ps1` | 被协议触发时执行：检查 8765 端口，未监听则隐藏窗口启动 `serve.py` |
| `serve.py`（`--idle-exit 180`） | 精选页内置 60 秒心跳保活；任何请求（心跳/反馈/页面加载）都会刷新 last_request，180 秒无请求则自行退出 |
| `userscript/bili-recs.user.js` | 打分条；「我的精选」入口（ping 判断在线状态并触发拉起）；离线打分缓冲（**不持续心跳**） |

## 5. W1 守护脚本（`watch.ps1`）

```powershell
# watch.ps1 —— 浏览器在则拉起 serve.py，浏览器全退出则停止服务
$root    = Split-Path -Parent $MyInvocation.MyCommand.Path
$python  = Join-Path $root ".venv\Scripts\python.exe"
$serve   = Join-Path $root "serve.py"
$browsers = @("chrome", "msedge", "firefox", "brave", "opera")

$proc = $null
while ($true) {
    $browserUp = @(Get-Process -Name $browsers -ErrorAction SilentlyContinue).Count -gt 0

    if ($browserUp -and -not $proc) {
        $proc = Start-Process -FilePath $python `
            -ArgumentList $serve, "--no-browser", "--idle-exit", "600" `
            -PassThru -WindowStyle Hidden
        Write-Host "[watch] 浏览器已启动 -> serve.py (PID $($proc.Id))"
    }
    elseif (-not $browserUp -and $proc) {
        Stop-Process -Id $proc.Id -Force -ErrorAction SilentlyContinue
        Write-Host "[watch] 浏览器已关闭 -> 服务停止"
        $proc = $null
    }
    elseif ($proc -and $proc.HasExited) {
        $proc = $null   # 服务自己退了（空闲自退），下次循环重新拉起
    }
    Start-Sleep -Seconds 5
}
```

## 8. 风险与边界

- **@connect 必须声明** `127.0.0.1`，否则请求被 Tampermonkey 拦截
- **mixed content**：https 页面访问 `http://127.0.0.1` 属浏览器规范豁免，不需 HTTPS
- **多浏览器并存**：watch.ps1 的进程名列表要覆盖你实际用的浏览器；两个浏览器都开着时服务保持运行
- **标签抓取不稳**：B站改版会导致 `.tag-panel` 选择器失效 → 打分照常提交，tags 用分区名兜底
- **重排是第二阶段**：先上"打分 + 离线缓冲 + 精选入口"，稳定后再做推荐流贴分/隐藏

## 9. "每日推荐"的语义：清单式（建议改成这个）

### 9.1 当前实现（有缺陷，需修正）

- `serve.py` **每次刷新都重新调用** `compute_picks(top=20)`，列表不是按天固定的
- 点了「满意」后：该视频**立刻成为训练样本**，但它**仍然可能出现在列表里**——
  因为 `candidates.csv` 是上一轮 collector 生成的，collector 只在运行时排除已打分视频
- 没有"10 条配额"概念，也没有"看过的就不再出现"

### 9.2 建议的清单式语义（"每日 10 条、看完即止、次日刷新"）

| 行为 | 设计 |
| --- | --- |
| 每天生成一次 | 当天首次打开时生成快照 `data/daily/YYYY-MM-DD.json`（默认 **10 条**），当天固定不变 |
| 排除看过的 | 生成快照时排除 `scores.csv` 中已有的 bvid，**不会再推荐你看过的视频** |
| 反馈后 | 该条标记为「满意 / 踩雷」并移到页面下方「已完成」区，不再参与当天排序 |
| 满 10 条 | 当天不再新增；可选「再给我 10 条」按钮应对当天全不感兴趣的情况 |
| 次日 | 首次打开自动生成新快照（候选来自你最近一次 `collector.py` 运行） |
| 强制重算 | 页面「重算今日」按钮，或 URL 加 `?refresh=1` |

**实现要点**

- 快照保存 `bvid, title, tags, pred_interest, pred_value, feedback(null/good/bad)`
- 页面顶栏显示「今日进度 3/10」
- 固定留 1~2 个探索位（低相似度候选），防回音室
- 快照随 git 同步，换机器能接着看同一份今日清单

### 9.3 两句话回答你的疑问

1. **点赞后会一直存在吗？** 现在会（缺陷，可能反复推荐同一条）；改成清单式后，打过分的不再出现
2. **是满 10 条就停、次日刷新吗？** 现在不是（每次刷新重算 Top 20）；改成清单式后就是你描述的这个语义
