# 需求文档：推荐体验升级（域外探索 · 两列布局 · 点赞管理）

- 文档日期：2026-09-10
- 状态：**已评审**（3 项关键决策已确认，见第 8 节）→ 待排期实现
- 关联文档：[B站个人推荐层实现方案.md](B站个人推荐层实现方案.md) · [优化清单.md](优化清单.md) · [油猴脚本与自动启停方案.md](油猴脚本与自动启停方案.md)

## 0. 背景与目标

当前版本（第 1 批已上线）具备：每日 10 条固定清单、三档反馈（喜欢/无感/踩雷）、"为什么推荐"、探索位、UP 主特征、排除已打分。

本次要解决的用户痛点：

1. 推荐仍集中在既有口味圈内，**缺乏"完全跳出当前 tag"的发现能力**
2. 单列卡片流信息密度低，**浏览效率不高**
3. 每日条数固定为 10 条，但**用户真正需要的是"10 个点赞"**，而不是"10 条清单"
4. 推荐过的内容没有沉淀，**没有可回顾、可撤销的点赞清单**

## 1. 需求总览

| 编号 | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| FR-1 | 域外探索推荐（跳出当前 tag） | P0 | 每日固定若干条"完全不在口味圈"的视频 |
| FR-2 | 推荐界面两列布局 | P1 | 桌面两列、移动单列 |
| FR-3 | 每日点赞目标 10（清单容量与终止条件） | P0 | 目标 10 个点赞；达到后不再追加；可以不足 10 |
| FR-4 | 全量记录（展示日志 + 反馈状态） | P0 | 展示过 / 点赞 / 无感 / 踩雷 全部落库 |
| FR-5 | 点赞列表页（回顾 + 撤销） | P0 | 可查看全部点赞，可撤销 |
| FR-6 | 页面导航与页签结构 | P1 | 今日清单 / 我的点赞 / 全部记录 |

## 2. 详细需求

### FR-1 域外探索推荐（跳出当前 tag）

**描述**
在每日清单中固定保留若干条**完全跳出当前 tag** 的推荐，用于试探新领域（不是"相似度略低"的候选，而是"基本不相关"的候选）。

**判定规则（必须可自动判定）**
一条候选被标为「域外探索」需同时满足：

1. 与"兴趣原型"的余弦相似度处于**当日候选池最低的 5%**（或低于阈值 θ，默认 `pred_interest < 3.2`）
2. 其**主分区不属于用户已打过分数的分区集合**（例如你从未给"舞蹈/时尚"打过分，则来自这两个分区的候选可入选）

**来源（按优先级）**
1. 用户**从未打分的分区**排行榜（需 collector 支持分区扩展）
2. **随机关键词搜索**结果（每期随机 3~5 个词，覆盖不同领域）
3. 总榜（rid=0）随机采样

**展示要求**
- 卡片带「🎲 域外探索」徽标
- "为什么推荐"显示：`域外探索：来自你从未涉及的【XX】分区`

**数量**（已确认）
- 每日 **1 条**（可配置 `--wild-explore 1`）
- 域外探索条**计入**当日点赞目标（不单独计数）
- **自动降频**：连续 7 天域外探索点赞率为 0 时，降为隔天 1 条，并记录降频原因

**验收标准**
- [ ] 当日清单中至少出现 1 条带「域外探索」徽标的候选
- [ ] 该候选的主分区不在"用户已打分分区集合"中（可用脚本断言）
- [ ] 连续 7 天统计域外探索的点赞率；若为 0，自动降频为每 2 天 1 条并记录原因

### FR-2 推荐界面两列布局

**描述**
推荐卡片由单列改为**左、右两列**展示，提升单位屏幕的信息密度。

**规格**
| 视口宽度 | 列数 | 说明 |
| --- | --- | --- |
| ≥ 1200px | 2 列 | 卡片等宽，间距 12px |
| 1000px ~ 1200px | 2 列（紧凑） | 卡片留白收紧 |
| < 1000px | 1 列 | 移动/窄屏保持单列 |

- 阅读顺序：**按行从左到右**（grid `auto-flow: row`），保证"第 1、2 条并排在第一行"
- 卡片内部信息层级不变：序号 / 标题（外链）/ UP 主 / 分区 / 匹配度条 / 预测兴趣·价值 / 为什么推荐 / 反馈按钮
- 卡片高度不一致时允许自然错落（不强制等高），但同一行的卡片顶部对齐

**验收标准**
- [ ] 浏览器窗口 ≥1200px 时为两列，缩到 <1000px 自动变单列
- [ ] 卡片顺序与清单顺序一致（第 1、2 条在同一行）

### FR-3 每日点赞目标 10（清单容量与终止条件）

**描述**
每日的目标是**攒够 10 个点赞**，而不是"看完 10 条"。清单本身可以多于 10 条（因为会有无感/踩雷挤占）。

**规格**
| 项 | 值 | 说明 |
| --- | --- | --- |
| 每日目标点赞数 | 10 | 可配置 `--like-goal 10` |
| 初始清单条数 | 14 | 可配置 `--daily-size 14`（默认 > 目标，留出无感/踩雷空间） |
| 追加机制 | 「再来几条」每次追加 5 条 | 当天累计上限 30 条（`--daily-max 30`） |
| 达到目标后 | 顶部提示「今日目标已达成 🎉」，**按钮禁用、不再追加** | 当天不再消耗候选 |
| 未达目标 | **允许**（例如只点了 6 个赞，其余是无感/踩雷） | 不做补救，直接用现有数据进入次日迭代 |
| 次日 | 用前一天全部反馈（点赞/无感/踩雷）重新训练并生成新清单 | 复用现有 `generate_daily` |

> **已确认：目标制** —— 满 10 个赞即停止追加；不足 10 个赞也正常进入次日迭代，不做补救。

**验收标准**
- [ ] 点赞数达到 10 时页面出现"今日目标已达成"，且无法再追加条目
- [ ] 点击「再来几条」后清单条数增加 5，但不重复出现已有条目
- [ ] 累计条数达到 30 条后，追加按钮禁用并提示"今日候选已用尽"

### FR-4 全量记录（展示日志 + 反馈状态）

**描述**
**推荐过的、点赞的、无感的、踩雷的，全部落库**，形成可追溯的历史。这是"下次迭代使用点赞数据"和"点赞列表可回顾"的数据基础。

**规格**
| 事件 | 记录内容 |
| --- | --- |
| 清单生成（展示） | 每个条目写入 history：bvid、标题、标签、UP 主、展示日期、来源、是否域外探索、当时预测分，`feedback` 初始为空 |
| 点赞 / 无感 / 踩雷 | 更新该条目的 `feedback` 字段（同时按现有逻辑写 `scores.csv`） |
| 撤销 | `feedback` 清空 + 删除 `scores.csv` 中对应记录，该视频可重新进入候选池 |
| 未反馈 | `feedback` 保持为空；仍全量记录，但**不永久排除**（只受冷却期限制） |

**重复推荐策略**（已确认：**只排除已反馈的**）
- **已反馈（liked / meh / bad）的条目**：永久不再推荐
- **仅展示过、未反馈的条目**：**可以再次推荐**，不会被永久排除
- 为避免同一条目天天刷屏，引入**冷却期** `--reshow-cooldown 3`：未反馈条目在最近 3 天内不重复出现
  （设为 `0` = 关闭冷却，次日即可再出现；设为 `7` = 更长的冷却）
- `history.csv` 仍**全量记录**每一次展示（用于统计与回顾），冷却判断只看"最近一次展示日期"

**验收标准**
- [ ] 生成清单后，`data/history.csv` 中每条都有记录，`feedback` 为空
- [ ] 反馈后对应行的 `feedback` 变为 `liked/meh/bad`
- [ ] 次日清单中**不出现任何已反馈（liked/meh/bad）的 bvid**
- [ ] 未反馈的条目在冷却期内（默认 3 天）不重复出现；超过冷却期后可重新出现
- [ ] 撤销后该行的 `feedback` 清空，且该视频能重新出现在候选池

### FR-5 点赞列表页（回顾 + 撤销）

**描述**
新增「我的点赞」页面，用于回顾所有点赞过的视频，并支持撤销。

**规格**
| 功能 | 说明 |
| --- | --- |
| 列表 | 按点赞时间倒序，展示：标题（外链 B站）、UP 主、分区、点赞时间、当时预测分、匹配度 |
| 撤销点赞 | 每行「撤销点赞」按钮 → 删除该评分 → 从列表消失 → 视频回到候选池 |
| 统计 | 顶部显示：累计点赞 N 条 · 本周 M 条 · 覆盖 UP 主 K 个 · 覆盖分区 J 个 |
| 排序/筛选 | 按时间倒序（默认）；可按分区、按 UP 主筛选（P2 可选） |
| 导出 | 「复制为 Markdown」按钮（P2 可选） |

**验收标准**
- [ ] `/liked` 列出全部点赞记录，数量与 `scores.csv` 中 liked 记录一致
- [ ] 点撤销后：列表少一条、`scores.csv` 少一行、`history.csv` 中该行 feedback 为空
- [ ] 统计数字随撤销实时更新（刷新页面即可）

### FR-6 页面导航与页签结构

**描述**
页面顶部增加页签导航，承载多个视图。

| 页签 | 路由 | 内容 |
| --- | --- | --- |
| 今日清单 | `/` | 两列推荐 + 进度（点赞 x/10） |

**验收标准**
- [ ] 三个页签可互相跳转，当前页签高亮
- [ ] 今日进度显示格式为「点赞 3/10 · 已看 5 条」

## 3. 数据模型变更

**新增 `data/history.csv`**

| 字段 | 说明 |
| --- | --- |
| bvid | 视频号（唯一键） |
| title / tags / author | 展示时的元数据快照 |
| shown_date | 首次展示日期（YYYY-MM-DD） |
| source | 候选来源：ranking / search / wild（域外探索） |
| is_explore | 是否探索位（0/1） |
| pred_interest / pred_value / match | 当时预测值 |
| feedback | 空 / liked / meh / bad |
| feedback_ts | 反馈时间 |

**`scores.csv`**：不变（bvid,title,tags,author,interest,value,ts），仍是训练数据源
**`data/daily/YYYY-MM-DD.json`**：扩展字段 `like_goal`、`likes`、`extended`（已追加次数）、`wild_count`

## 4. 接口变更（serve.py）

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/liked` | GET | 点赞列表页 |
| `/history` | GET | 全部记录页 |
| `/api/reveal-more` | POST | 追加 5 条（受目标与上限约束） |
| `/api/feedback` | POST | 已有：`{bvid, kind}` 或 `{bvid, undo:true}`；**新增同步更新 history** |
| `/api/stats` | GET | 点赞数、已看数、目标进度（P2） |

## 5. 交互流程

```
打开页面 → 今日清单（两列，14 条 = 12 条常规 + 1 条域外探索 + 1 条探索位）
   ├─ 点标题 → B站观看
   ├─ 点「喜欢」→ 进度 +1；达到 10 → 顶部提示"目标达成"，停止追加
   ├─ 点「无感 / 踩雷」→ 记录，不计数
   ├─ 点「再来几条」→ 追加 5 条（目标未达成且未超上限时可用）
   └─ 切到「我的点赞」→ 回顾列表 → 撤销某条 → 该视频回到候选池
次日 → 用前一天全部反馈重训 → 生成新清单（已展示过的不再出现）
```

## 8. 已确认决策与遗留问题

**已确认（2026-09-10）**

1. 「每日 10 个点赞」= **目标制**：满 10 赞即停止追加；不足 10 赞也正常进入次日迭代
2. 重复推荐策略 = **只排除已反馈的**：展示过但未反馈的条目可以再次推荐（配合默认 3 天冷却期防止刷屏）
3. 域外探索 = **每天 1 条**；连续 7 天点赞率为 0 时自动降频为隔天 1 条

**遗留待确认**

1. 两列阅读顺序：按行（第 1、2 条并排）是否符合预期？还是按列（左列 1~7、右列 8~14）？
2. 点赞列表是否需要导出（Markdown / CSV）？
3. 未反馈条目的冷却期 3 天是否合适（可改 `0` 关闭 / `7` 更长）？
4. 域外探索自动降频后，是否需要"恢复条件"（例如点赞率回升则恢复每天 1 条）？
