# 视频推荐想法整理

> 核心想法：不再信任"以流量为王"的平台自动推荐，改用自己显式打出的"价值分"，养一个更贴近本人的推荐。—— 这个想法成立，下面是完整拆解。

## 一、你观察到的问题，其实是三层

| 层次 | 现象 | 本质 |
| --- | --- | --- |
| 内容层 | 优质劣质视频混杂 | 平台不负责质量，只负责分发 |
| 机制层 | 流量为王，情绪输出泛滥 | 算法的目标函数是"时长/点击"，情绪化内容天然占优 |
| 反馈层 | "看了一眼的垃圾"也被当成兴趣 | 平台主要用隐式反馈（观看行为），噪声极大 |

核心矛盾一句话：**平台的算法在优化"平台想要的东西"（停留时长→广告），而不是"你想要的东西"（价值）。**

## 二、你的想法，翻译成专业语言

"显式打分养推荐"就是推荐系统里的 **显式反馈（explicit feedback）**；平台现在主要用的是 **隐式反馈（implicit feedback）**——点击、停留、完播率。

| | 数据量 | 信号质量 | 问题 |
| --- | --- | --- | --- |
| 隐式反馈 | 巨大 | 噪声大 | 分不清"我想看"和"我被骗进去看了" |
| 显式反馈 | 稀疏 | 很高 | 打一次分，胜过一万次误点 |

- 你的直觉是对的：显式反馈是经典做法——豆瓣评分、早期 YouTube 星级、B站一键三连，都是显式信号。
- 平台为什么放弃它？表面原因：打分率太低，撑不起全体用户。根本原因：显式打分优化的"价值"与平台的商业目标（时长）冲突。**不是算法做不到，是不想做。**
- 由此得出这个想法里最值钱的结论：**问题不在算法，在"目标函数由谁定义"。你自己做，就是把目标函数的定义权夺回来，定义成"我的价值分"。**

## 三、一个必须想清楚的概念区分：兴趣 ≠ 价值

"我感兴趣"和"我认为有价值"是两个不同的轴：

| | 我感兴趣 | 我不感兴趣 |
| --- | --- | --- |
| 质量高 | ✅ 理想区 | ⚠️ 硬核内容，容易被错过 |
| 质量低 | ⚠️ 爽文/情绪流 | ❌ 垃圾 |

如果打分只有一个维度，就会把这两件事搅在一起。建议打分设计成两维：**兴趣分 + 价值分**——至少你要清楚自己在打的是哪一个。

## 四、显式打分方案的四个现实问题（提前打预防针）

1. **冷启动**：打分是稀疏信号，你得先看几十上百个视频并打分，算法才学得会；初期体验会很差。
2. **打分疲劳**：不可能看一个打一个。解法：低摩擦设计——"只为值得打分的内容打分"（比如双键：喜欢/不喜欢，只在明显超出或低于预期时打分）。
3. **兴趣漂移**：半年前的分数不能永远等权，需要时间衰减。
4. **回音室风险**：纯显式打分会让推荐越来越窄；需要保留一小部分"探索"流量去撞新东西。

## 五、四条可选路线（从轻到重，不互斥）

**A. 零代码：驯服现有平台**
主动用"不感兴趣""不推荐该频道"、清理历史、关闭个性化；用订阅和 RSS 当自己的"编辑团队"。成本最低，但治标不治本，且发现新内容仍靠平台。

**B. 个人推荐层（最值得先做）**
浏览器插件或本地程序：你给看过的视频打价值分 → 抓取视频元数据 → 本地跑一个小模型（内容相似度 + 你的分数）→ 把平台的推荐流重排/过滤，或生成一份"我的每日精选"。技术上完全可行，起步甚至不需要深度学习。局限：只能重排已经出现在你面前的内容，发现新内容的能力弱。

**C. 自己写一个推荐算法（学习实验）**
用公开数据集（如 MovieLens）或自爬数据，动手实现协同过滤 / 内容推荐 / 排序模型。做完你会真正理解"算法没罪，目标函数有罪"。适合作为 B 的前置练习。

**D. 做给别人用（社区/产品，最难）**
做一个以显式打分为核心的策展社区：只做"打分 + 推荐"这一层，内容跳转到原平台。可参考：豆瓣评分、Hacker News（投票+时间衰减）、早期 B站。难点不在算法，在社区治理：谁打分？为什么打？怎么防刷？冷启动内容从哪来？

## 六、下一步：你只需要做四个决定

1. **受益人**：自己（工具）还是公众（产品）？
2. **价值定义者**：你自己 / 社区共识 / 双轴？
3. **内容来源**：现有平台当数据源（聚合层），还是自建内容？
4. **投入边界**：你的技术能力和时间。

## 七、建议起点

先用 1~2 周做 B+C 的结合——一个最小原型：你给视频打"价值分"，本地跑一个简单的基于内容的推荐，验证"显式打分养出来的推荐，是否真的更贴近你"。这个实验成本低，而且无论结果如何都会回答两个问题：你真正想要的是"工具"还是"产品"；"显式打分"这条路值不值得继续走。

## 八、根据你的四个选择定出的路线

**选择汇总**：个人推荐层原型（B）· 兴趣+价值双轴打分 · Python 教学式实现 · 现有平台当数据源。

**MVP 分三步**：

1. **第 1 步（1~2 天）：跑通"打分 → 推荐"闭环（纯本地）**
   - Python 脚本 + CSV 存分数
   - 给看过的视频打双轴分：`python score.py "标题" --interest 4 --value 5`
   - 推荐器：TF-IDF 相似度 + 双轴加权，对新候选预测兴趣分/价值分并排序
   - 目标：用 30~50 条打分验证"显式打分能不能养出更懂我的推荐"，同时学会推荐系统的核心概念
2. **第 2 步（降摩擦）：在平台上直接打分**——油猴脚本在 B站/YouTube 页面加两个打分按钮（兴趣 1~5 / 价值 1~5），存 localStorage，导出 JSON 喂给推荐器
3. **第 3 步（自动化）：生成"每日精选"**——拉订阅频道新视频 + 部分平台推荐作为候选池，本地过滤低价值预测、按兴趣预测排序，输出每日 top 10，保留 10~20% 探索位防回音室

**技术栈**：Python + scikit-learn（TF-IDF）+ CSV/JSON + 可选 Tampermonkey + yt-dlp。不碰深度学习和 LLM——几十条打分根本不需要。

**能回答什么**：显式双轴打分是否比平台隐式推荐更贴近你；你实际能接受多少打分摩擦。
**不能回答什么**：发现全新内容的能力（需要更大候选池，第 3 步只是开始）。

> 完整实现方案见 [B站个人推荐层实现方案.md](B站个人推荐层实现方案.md)（架构 / 数据模型 / 候选池 / 双轴算法 / 里程碑 M1~M4 / 风险对策）。

### 调研后的三个判断

1. 别造算法轮子——时间花在目标函数和打分交互上，那才是想法的本体
2. "双轴显式打分的个人推荐层"是空白：最接近的两个一个停更、一个刚出生，且都缺显式打分
3. 差异化增量：显式双轴打分 + 数据主权（全本地）+ B站中文生态（现有项目几乎只做 YouTube 英文）

## 一句话总结

问题不在算法，在"目标函数由谁定义"；你的想法本质是夺回目标函数的定义权——这成立，下一步是选战场。
