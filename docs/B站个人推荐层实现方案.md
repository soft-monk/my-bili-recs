# B站个人推荐层实现方案（双轴显式打分版）

> 目标：做一个只属于你自己的 B站推荐层——你给看过的视频打"兴趣分"和"价值分"，本地模型学出你的口味，把候选视频过滤、排序，输出"每日精选"。
> 核心主张：把目标函数的定义权从平台夺回来，定义成"我的价值分"。

## 0. 目标与边界

**做什么**
1. 打分入口：看视频时给"兴趣"和"价值"各打 1~5 分
2. 本地推荐引擎：内容相似度 + 双轴分，全本地运行
3. 每日精选：从候选池过滤垃圾、按你的口味排序，输出 top 10

**不做什么（起步阶段）**
- 不做平台、不做社区（那是方案 D）
- 不碰深度学习大模型（几十条打分用不上）
- 不依赖 B站官方推荐流作为主要来源（避免垃圾进垃圾出）

**成功标准（可量化）**
- 每日精选 10 条的"你满意率" > B站官方推荐流 10 条的满意率
- 具体做法：每天给两组各 10 条标记"看了/满意/踩雷"，每周统计对比

## 1. 总体架构

```
┌─────────────┐   ┌──────────────┐   ┌─────────────┐   ┌──────────────┐
│ 打分入口     │   │ 分数库        │   │ 推荐引擎     │   │ 每日精选      │
│ 油猴按钮/CLI │──▶│ scores(SQLite)│──▶│ 双轴原型向量  │──▶│ top10 HTML    │
└─────────────┘   └──────────────┘   │ + 相似度排序  │   └──────────────┘
                                     └──────────────┘
┌─────────────┐   ┌──────────────┐         ▲
│ 候选池收集   │──▶│ videos(SQLite)│─────────┘
│ 订阅/榜单/低频│   │ 元数据缓存     │
└─────────────┘   └──────────────┘
```

- 全本地、无服务器；每天一条命令：`python main.py update && python main.py serve`
- 任何一步失败都不影响已有数据（打分是最贵资产，永远优先保存）

### 1.1 日常使用循环（一次起步，之后自动转）

```
                      ┌──────────────────────────┐
                      │   一个分数库（唯一数据源）  │
                      └──────────────────────────┘
                         ▲ 写                     │ 读
                 任何地方打分                    每天一次更新模型
                         │                       ▼
        ┌─────────────────────┐         ┌───────────────────┐
        │  触点1：B站播放页      │  跳转    │  触点2：每日精选页    │
        │  油猴按钮：兴趣★ 价值★ │◀──播放──│  top10 卡片          │
        │  （平时刷B站顺手打）    │         │  按钮：满意 / 踩雷    │
        └─────────────────────┘         └───────────────────┘
```

1. **起步（只做一次）**：翻历史记录/收藏夹，给已看过的 30~50 个视频回顾式打分，解决冷启动
2. **每天一次**：读分数库全部分数 → 更新双轴原型 → 拉当日候选 → 过滤低价值 → 按兴趣排序 → 生成精选页 top10
3. **看推荐**：精选页点卡片 → 跳 B站播放页观看
4. **打分**：B站页面油猴按钮（主动、细粒度）或精选页"满意/踩雷"（反馈、粗粒度），写同一个库
5. **回到第 2 步**，第二天模型已更新

**关键澄清**：
- "10" 是每天推荐条数，**不是训练批次**——训练永远用全部历史分数，没有"凑够几条才训练"
- B站页面与精选页不是两个系统，是同一循环的两个触点，中间只隔一个分数库
- 推荐每天批量生成一次（不是实时）；方案 B 的页内重排也只是展示提前算好的分数

## 2. 数据模型

**videos 表**（视频元数据缓存）
| 字段 | 说明 |
| --- | --- |
| bvid | 主键，BV 号 |
| title / desc / tags | 标题 / 简介 / 标签（特征来源） |
| tname | 分区（知识/科技/生活…，重要特征） |
| owner / pubdate / duration | UP主 / 发布时间 / 时长 |
| stat | 播放/弹幕/收藏/投币/点赞（备用弱特征） |

**scores 表**（你的双轴打分——最贵资产）
| 字段 | 说明 |
| --- | --- |
| bvid | 视频 |
| interest | 兴趣分 1~5（口味：个性化排序用） |
| value | 价值分 1~5（质量：垃圾过滤用） |
| ts | 打分时间（做时间衰减） |

**双轴语义**：interest 管"我喜不喜欢"，value 管"这东西值不值得看"。两条轴在模型里走两条独立通路，绝不混成一个分。

## 3. 候选池（内容从哪来）

按优先级排序，**不把平台推荐流当主来源**：

| 优先级 | 来源 | 获取方式 | 说明 |
| --- | --- | --- | --- |
| 1 | 订阅 UP 主新投稿 | bilibili-api-python 的 space 接口，或 RSSHub `/bilibili/user/video/{uid}` | 你主动选择的信源，质量基线最高 |
| 2 | 分区排行榜 | `x/web-interface/ranking/v2?rid={分区}` | 有底线，可发现分区内新面孔 |
| 3 | 浏览时顺手打分 | 油猴脚本自动记录页面元数据 | 你实际在看的东西 |
| 4 | 历史记录/收藏夹导入（可选） | 登录 cookie + API | 冷启动加速，一次性导入 |
| 5 | 平台推荐流低频采样 | 登录 cookie + 低频（每天 ≤ 20 条） | 当"探索"来源——故意让垃圾进来，再让模型过滤 |

频率纪律：每日一次，总量 < 100 请求，用自己账号的 cookie，不碰下载、不碰弹幕接口。

## 4. 打分交互（摩擦最低化）

三层递进，先糙后细：

1. **CLI（里程碑 1）**：`python score.py BV1xx4y1z7Ab --interest 4 --value 5`
2. **本地打分板（可选中间态）**：粘贴 bvid 自动拉标题，网页里点星
3. **油猴脚本（里程碑 3）**：视频页注入两个星级条（兴趣 ★★★★★ / 价值 ★★★★★），存 localStorage，导出 JSON 合并入库。注入方式参考 the1812/Bilibili-Evolved

设计原则：**只为"明显超出或低于预期"的视频打分**，不打分的视频不进训练样本——稀疏但干净，正是显式反馈的优势。

## 5. 算法（核心，教学友好）

### 5.1 特征向量
- 中文分词 jieba → 标题 + 简介 + 标签 + 分区 加权拼接 → TF-IDF 向量（scikit-learn）
- 升级选项：BAAI/bge-small-zh-v1.5 等中文 embedding（国内用 hf-mirror.com 下载），效果好一档，但 M1 不必上

### 5.2 双轴原型向量
```
口味原型 v_interest = 归一化( Σ (interest_i − 3) × vec_i )   # 兴趣分高于3的拉近，低于3的推远
质量原型 v_value    = 归一化( Σ (value_i − 3) × vec_i )      # 价值分同理
```
你打分过的每个视频都用两轴各投一次票，得到"你爱什么"和"什么值得看"两个独立原型。

### 5.3 预测与排序
1. `pred_value = cosine(候选, v_value)` 映射到 1~5 → **过滤** `pred_value < 3`（垃圾拦截）
2. `pred_interest = cosine(候选, v_interest)` 映射到 1~5 → **排序**
3. 约束：同一 UP 主 ≤ 2 条；可选时间衰减（半衰期 7 天）
4. 末尾 10~20% 位置插探索项（低相似度/随机），防回音室

### 5.4 为什么不用协同过滤
单人场景下 user-item 矩阵只有一行，CF 没有意义。个人推荐层天然是 **content-based + 你的显式打分**。协同过滤留给未来社区版（方案 D）——这也是 C 阶段学 Surprise 时要看清的一点。

### 5.5 评估
每天两组各 10 条（我的精选 vs 官方推荐流）标记"看了/满意/踩雷"，周度对比满意率。这就是单人的极简 A/B，也是"用我的价值分做目标函数"的量化证据。

## 6. 技术选型

| 组件 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.10+ | 生态最全，教学友好 |

| 分词/向量 | jieba + scikit-learn TF-IDF | 零模型下载，国内无障碍 |
| 可选升级 | sentence-transformers + bge-small-zh | 语义相似度更好，需 hf-mirror 下载模型 |
| 存储 | SQLite（起步 CSV 也行） | 内建、单文件、够用到几千条 |
| 打分 UI | Tampermonkey 油猴脚本 | 参考 Bilibili-Evolved 注入方式 |
| 输出 | 纯静态 HTML 生成 | 无需常驻服务器；可选 Flask |

## 11、推荐结果怎么送到你面前（最后一公里）

### A. 本地"每日精选"页（M2 默认）

- 形态：`serve.py` 每天生成一个静态 HTML——卡片流（封面/标题/UP主/时长/预测兴趣分/预测价值分/你的历史分），点击跳转 B站播放页
- 到达方式：浏览器书签、设为浏览器主页、双击打开；同一局域网内手机浏览器可访问电脑 IP
- **关键设计：每张卡片带反馈按钮「看了 / 满意 / 踩雷」→ 点击写回分数库 → 明天模型更新。反馈按钮比推荐列表本身更重要**（它是下一轮训练数据 + 周度 A/B 评估数据，没有它模型就断了进化）
- 优点：零部署、全本地、隐私最好；不需要服务器

### B. B站页面内重排（M4 实验，最贴场景）

- 形态：油猴脚本在 B站首页/推荐流卡片上贴预测分、高兴趣置顶高亮、低价值隐藏并提示"已过滤"
- 原理：脚本从本地 localhost 服务（Flask）读取当日分数表，或把分数表塞进 localStorage 离线重排 → MutationObserver 监听动态加载的卡片 → 修改 DOM
- 诚实提醒：B站首页是动态瀑布流、结构改版频繁，属于实验性功能，需持续维护；更稳的形态是"把入口从 B站首页换成你的精选页"
- 优点：不碰 B站接口、无风控风险；你正常刷 B站就生效

### C. 推送（M4 可选，手机场景友好）

- 微信（Server酱 / 企业微信机器人）、Telegram Bot、邮件：每天把 top10 图文发到手机
- 优点：被动到达，不用记得打开；贴合手机刷 B站
- 代价：外部依赖；点开是网页链接，体验弱于原生 App

### D. RSS（可选）

- 生成每日精选的 RSS feed，用任何阅读器订阅（FreshRSS / Miniflux / 手机阅读器）
- 适合本来就有 RSS 习惯的人

### 路线与原则

- 顺序：M2 先做 A（静态 HTML，零服务器）→ 需要"打开 B站即被重排"再做 B（需要 localhost 服务）→ 手机被动接收再加 C
- 原则 1：**推荐出口必须带反馈入口**，否则没有下一轮数据
- 原则 2：桌面优先、手机后补——你平时在哪刷 B站，决定 B 和 C 的优先级

## 一句话设计哲学

**算法很朴素（TF-IDF + 余弦相似度就够起步），玄机全在目标函数——把排序的依据从"平台要的时长"换成"你打的价值分"，生态问题在你个人这里就解了。**
